# Публичные голосовые сессии (Node.js + WebRTC)

Проект позволяет пользователю явно включить микрофон, создать временную голосовую сессию, а слушателям — открыть список и выбрать сессию. Аудио передаётся через WebRTC напрямую между браузерами; Node.js используется для сигнализации и списка активных сессий. Аудиофайлы сервером не записываются.

## Быстрый локальный запуск

Требуется Node.js 18 или новее.

```bash
npm install
npm start
```

В терминале появится адрес. По умолчанию это `http://localhost:3000` (если порт занят, сервер попробует следующие порты).

- Страница говорящего: `/transmit`
- Страница слушателя: `/listen`

## Публикация для доступа из интернета (Render)

В архив уже добавлен `render.yaml`. Деплой выполняется через GitHub и Render; файл ZIP нельзя просто открыть как публичный сайт — Node.js-сервер должен работать на хостинге.

1. Распакуйте архив. В корне должны быть `package.json`, `server.js`, `render.yaml` и папка `public`.
2. На GitHub создайте новый репозиторий. Самый простой вариант через сайт: зайдите на https://github.com/new, создайте репозиторий, затем в нём выберите **Add file → Upload files** и перетащите в окно файлы `package.json`, `server.js`, `render.yaml`, `.gitignore`, `README.md` и папку `public` из распакованного проекта. Важно: загрузите сами файлы и папку, а не ZIP-архив.
3. Откройте Render и войдите в аккаунт: https://render.com/ .
4. В Render выберите **New → Web Service** и подключите созданный репозиторий. Если запускаете через Blueprint, Render может прочитать настройки из `render.yaml`. Укажите параметры:
   - Runtime: Node
   - Build Command: `npm install`
   - Start Command: `npm start`
   - Health Check Path: `/`
   - Environment: `NODE_ENV=production`
5. Дождитесь статуса **Live** и откройте публичный HTTPS URL Render, например `https://ИМЯ-СЕРВИСА.onrender.com`.
6. Говорящий открывает `https://ИМЯ-СЕРВИСА.onrender.com/transmit`, нажимает «Начать сессию» и разрешает микрофон. Слушатель открывает `https://ИМЯ-СЕРВИСА.onrender.com/listen` и выбирает трансляцию.

Обе страницы по умолчанию используют WebSocket-сигнализацию на том же домене. В HTTPS-среде браузер автоматически подключается через WSS. Для этой конфигурации менять `public/config.js` не требуется.

## Важные ограничения публичного демо

- Список сессий общедоступен: посетители страницы `/listen` могут видеть активные трансляции и пытаться подключиться. Не передавайте конфиденциальный звук. Для приватного использования добавьте авторизацию/приглашения.
- Владелец микрофона должен сам начать сессию, подтвердить публикацию в общем списке и разрешить браузеру доступ к микрофону. Завершение сессии прекращает захват.
- Активные сессии хранятся в памяти процесса. Если хостинг перезапустит сервер, текущие сессии завершатся.
- Бесплатные инстансы Render могут засыпать после периода бездействия и долго просыпаться. Это нормально для теста, но не подходит для постоянно доступного голосового сервиса; изучите текущие ограничения тарифа перед публикацией.
- WebRTC старается передавать аудио напрямую. В некоторых сетях NAT/firewall может блокировать прямую связь; для более надёжной работы через разные сети потребуется TURN-сервер. Без TURN нельзя гарантировать, что каждый слушатель подключится из любой сети.
- В текущем демонстрационном варианте любой посетитель страницы `/listen` видит список сессий и может попытаться подключиться. Не используйте для приватных разговоров без аутентификации/приглашений. Сервер по умолчанию принимает только same-origin WebSocket-подключения; для размещения слушателя на другом домене настройте `ALLOWED_ORIGINS`.

## Отдельный сайт слушателя

Если страницу слушателя нужно разместить на другом домене, в `public/config.js` задайте `SIGNAL_URL` равным `wss://ИМЯ-СЕРВИСА.onrender.com/signal`, а файлы страницы слушателя и `config.js` разместите на другом сайте. На сервере задайте `ALLOWED_ORIGINS` как список точных origin-адресов через запятую, включая домен сервера-передатчика и отдельный домен слушателя (например, `https://voice.example.com,https://listener.example.com`). Если обе страницы находятся на том же Render-домене, это не требуется.

## Если порт 3000 занят локально

Сервер автоматически попробует следующий порт и напечатает фактический адрес. На хостинге используется предоставленная платформой переменная `PORT`.
